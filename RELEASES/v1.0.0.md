# Release v1.0.0 — Experimental Snapshot

Release date: 2026-09-06

Summary
- This is an experimental snapshot of the linux-rust repository. The repository contains large portions of AI-generated code produced with Google Gemini 3.8 and curated/edited by human contributors. This release primarily standardizes documentation, attribution, and safety guidance; it does not introduce functional changes to the kernel code.

Model / tooling used
- Generative model: Google Gemini 3.8
- Supporting tooling: custom prompt chains and generation pipelines (internal). See docs/ai_attribution.md for tracking guidance.

AI-generated components
- Broad code scaffolding and many source files across the repository were generated by the model during earlier development. Precise file-level mappings are not exhaustive; see docs/ai_attribution.md and CHANGELOG.md for best-effort mapping.

Human-curated / edited components in this release
- README.md — rewritten for clarity and transparency about AI involvement
- CONTRIBUTING.md — added contributor guidance and reviewer checklist for AI-generated code
- BUILD.md — added high-level build/run guidance with safety warnings
- CHANGELOG.md — added Unreleased entry and templates
- RELEASE_NOTES.md — added release-note template and example
- docs/ai_attribution.md — added policy and tracking guidance
- docs/RELEASE.md — added release process and auditability steps
- LICENSE — MIT license added to repository root

Validation performed for this release
- Manual review and editing of documentation files listed above.
- No automated code-level validation (build, unit tests, static analysis) was performed as part of this release.

Known issues and limitations
- The codebase remains experimental and may not build or boot as a kernel. Many generated subsystems may be incomplete, incorrect, or unsafe.
- AI-generated content may contain subtle logic, security, or licensing issues that require human review before reuse.
- This release focuses on documentation transparency and does not guarantee code stability.

Security and usage guidance
- Do not run kernel-level artifacts produced by this repository on production hardware.
- Test only in isolated VMs or emulators (QEMU) and prefer static analysis and code review before execution.
- Report security-sensitive findings privately to the repository owner for responsible disclosure.

How we recorded provenance
- See docs/ai_attribution.md for policy on how AI-generated files are tracked and how to document edits.
- CHANGELOG.md contains a release-oriented record; future releases should list specific file mappings and validation artifacts.

Recommended follow-ups
- Add CI that performs a reproducible build in a container and records toolchain versions and artifacts.
- Add explicit per-file provenance metadata (headers or a machine-readable registry) linking generated files to generation runs/prompts.
